# 用实际暗室生成 MPDB 空口工程

在信道工作台导入下行 MPDB 后选择“空口（OTA）”。工作台读取当前实验室绑定的暗室、启用的探头、射频拓扑，以及源载频下已采用的实际路径校准。检查不通过时，可在相应配置页修正，再点“重新核对暗室配置”。不要为了通过检查修改探头的连接状态；应先核实现场接线。

### 登记现场接线

“实际暗室安装登记”接受 JSON 文件。实验室已在 `extra_metadata.mpdb_ota_installation` 保存同样登记时可以直接使用。登记应来自现场接线核对，以下字段说明用于制作登记：

| 字段 | 取值依据 |
|---|---|
| `lab_profile_id`、`chamber_id`、`topology_id` | 实验室、所绑定暗室、当前工作模式射频拓扑的记录标识 |
| `tx_inputs` | 对象。键是 MPDB 的发射端口号，值是现场接入的 F64 输入口名称。每个发射端口独占一个输入 |
| `feeds` | 对象。键是启用的探头极化端的数据库 UUID。每条记录包含 `chain_id`（已采用校准的通路编号）、`ce_port`（该通路的仿真器输出）、`basis` 和 `positive_basis_confirmed` |
| `basis` | 取 `theta` 或 `phi`。分别沿天顶角增加、方位角增加的局部电场轴。确认安装轴及极性一致后才填 `positive_basis_confirmed: true`。当前计算支持同位置两条正交轴；倾斜、反接或缺一极化时无法直接使用 |
| `fit_points_m`、`check_points_m` | 同一暗室坐标系内的两组三维坐标，单位米，以测试区中心为原点。一组计算探头权重，另一组独立核对，点位不能重合 |

位置、已连接状态和登记的信道仿真器输出口由暗室探头记录提供。校准数值、频率、参考面和来源标识由服务读取。安装登记只把具体实物、极化和通路关联起来。工作台逐项核对当前射频拓扑中启用的基站到仿真器下行接线及输入端口名称；插口实际连接和设备许可仍须现场核实。

### 下载和使用

生成时再次核对当前配置。工程包的基线和动态清单均保存本次暗室信息、发射输入对应关系、每个探头索引对应的实物极化端及路径校准。查看 `geometry.probe_connections` 可将 ASC 文件名里的逻辑探头索引对应到实际输出。

空间权重按实际布设方向和登记的局部极化轴计算，仍使用平面波传播模型。场误差表示模型计算结果。路径损耗保存在清单中，ASC 未内嵌射频路径补偿；准备设备播放时必须核对并仅施加一次。设备工程构建、真实相位、暗室场分布和播放效果需在现场验收。
