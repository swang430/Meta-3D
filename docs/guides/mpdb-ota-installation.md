# 用实际暗室生成 MPDB 空口工程

在信道工作台导入下行 MPDB 后选择“空口（OTA）”。工作台读取当前实验室绑定的暗室、启用的探头、射频拓扑，以及源载频下已采用的实际路径校准。检查不通过时，可在相应配置页修正，再点“重新核对暗室配置”。不要为了通过检查修改探头的连接状态；应先核实现场接线。

### 登记现场接线

“实际暗室安装登记”接受 JSON 文件。实验室已在 `extra_metadata.mpdb_ota_installation` 保存同样登记时可以直接使用。登记应来自现场接线核对，以下字段说明用于制作登记：

| 字段 | 取值依据 |
|---|---|
| `lab_profile_id`、`chamber_id`、`topology_id` | 实验室、所绑定暗室、当前工作模式射频拓扑的记录标识 |
| `tx_inputs` | 对象。键是 MPDB 的发射端口号，值是现场接入的 F64 输入口名称。每个发射端口独占一个输入 |
| `feeds` | 对象。键是启用的探头极化端的数据库 UUID。每条记录包含 `chain_id`（已采用校准的通路编号）、`ce_port`（该通路的仿真器输出）、`basis` 和 `positive_basis_confirmed` |
| `basis` | 取 `theta` 或 `phi`。分别沿天顶角增加、方位角增加的局部电场轴。确认安装轴及极性一致后才填 `positive_basis_confirmed: true`。当前计算支持同位置两条正交轴；倾斜、反接或缺一极化时无法直接使用 |
| `fit_points_m`、`check_points_m` | 同一暗室坐标系内的两组三维坐标，单位米，以测试区中心为原点。一组计算探头权重，另一组独立核对，点位不能重合 |

位置、已连接状态和登记的信道仿真器输出口由暗室探头记录提供。校准数值、频率、参考面和来源标识由服务读取。安装登记只把具体实物、极化和通路关联起来。工作台逐项核对当前射频拓扑中启用的基站到仿真器下行接线及输入端口名称；插口实际连接和设备许可仍须现场核实。

### 按设计接线生成开发工程

现场可以按设计调整接线时，在“暗室安装登记或开发接线设计”中选择本实验室已登记的接线设计 JSON。服务会与实验室的 `extra_metadata.mpdb_ota_wiring_design` 比对，核对源发射端口、启用探头及其位置和极化。每条设计输出必须独占一个 F64 输出口。预览中可以展开“查看逐路设计接线”。

这条路径生成的基线和动态 ASC 使用同一份接线设计。工程清单将硬件验证和路径损耗标为未核验，逐路损耗留空。正式播放前仍须核对实物、极化方向和当前频点的路径校准。

### 下载和使用

生成时再次核对当前配置。工程包的基线和动态清单均保存本次暗室信息、发射输入对应关系、每个探头索引对应的实物极化端及路径校准。查看 `geometry.probe_connections` 可将 ASC 文件名里的逻辑探头索引对应到实际输出。

空间权重按实际布设方向和登记的局部极化轴计算，仍使用平面波传播模型。场误差表示模型计算结果。路径损耗保存在清单中，ASC 未内嵌射频路径补偿；准备设备播放时必须核对并仅施加一次。设备工程构建、真实相位、暗室场分布和播放效果需在现场验收。

### 按调制信号的占用频点核对场能量

在原始 ZIP 根目录随下行 MPDB 放入可选的 `ota-spectrum.json`。例如：

```json
{"source_sha256":"替换为本次 R0B0S0D.mpdb 的 SHA-256","offsets_hz":[-10000000,0,10000000],"relative_bin_power":[1,2,1]}
```

频偏相对于 MPDB 载频，每个权重是该频点的相对平均功率。填写实际占用的子载波和相对功率；若输入为谱密度，应先乘各频段宽度换成频段功率。该离散谱按频点功率加权，默认不同频点交叉项在统计时间内平均为零。源帧内沿用载频的射线幅度与极化，按逐径时延和空间传播距离推进各频点相位。

下载包内的 `baseline/field-spectrum.json` 按源帧、单独激励的发射口及独立空间点给出原始射线、回读 ASC 的相对电场模方加权平均及两者之比。原场为零时比值留空。报告仅对应填写的谱和基线源帧；动态帧间、多个发射口同时激励、探头实测频响及车辆天线插口绝对功率均须另有依据。未提供频谱时仍可生成工程，固定三个频点的场误差供逐点查看。

### 回读动态工程

用可导入 ChannelEngine 的 Python 在仓库根目录运行
`python -m scripts.verify_dynamic_ota 输入.zip 解压后的工程目录 核验结果.json`。
输入 ZIP 需包含同源 MPDB 和上一节的发射谱；工程目录须含 dynamic/manifest.json 及其 ASC。
使用独立核对点和文件中的实际播放行；若末源帧不落在网格上，不补造一个末样点。频点功率用于加权模方；各占用频点的相对相位分别检查，避免直接平均角度掩盖相消。

每段分别比较以下模型。各项最差位置可以不同，不能把各项极值相加：
- doppler_effect：相同的两端平滑混合，比较冻结逐径相位与按各径多普勒推进。差异表示采用推进对模型的影响。
- cluster_delay_effect：两侧均推进，仅把原始逐径时延替换为该端源帧的簇代表时延。
- probe_fit_and_delay_interpolation：上述压缩模型与回读 ASC 的差异，合含空间拟合、两端抽头槽位之间的时延插值及文件数值精度。
- probe_projection_only 和 tap_compression_after_projection：用未压缩逐径时延先单独求探头投影的误差，再比较投影场与实际 ASC，后一个差异包含压缩及抽头时延插值。此顺序与先压缩时延的对照共用同一终点。
- total_model_difference：原始逐径双端推进模型与回读工程的差异。帧间缺独立传播真值，以上均为模型对照。另用左源帧冻结和单边多普勒预测下一源帧，与该端 MPDB 的场能量比较；这里仍包含路径生灭、幅度和方向变化及时间轴误差。

每项报告段内有效数量、排除数量、绝对误差第 95 百分位及最差行。空间相位取两个发射口三分量电场复内积的相角；内积模不超过两场模长乘积的 1e-10 时排除。探头馈口另比较同一极化上两个发射口的相对相位与未压缩时延的投影参考，极弱馈口排除。行号和核对点序号从 0 起，发射端口沿用原 MPDB 编号。

要预测车载天线插口的绝对功率，还需各发射口实际占用频谱及绝对功率、同时发射时各频点的预编码或互相关、MPDB 场单位和发射参考面、暗室探头到测试区的绝对复场响应、车辆安装状态下各接收天线的复方向图或矢量有效长度、位置姿态及极化基准、插口阻抗和失配/馈线参考面。已计入 MPDB 的天线或损耗应注明。接收机合并后的功率还需合并权重。现场单列核对探头幅相与宽带响应、播放时序和插口实测；离线场能量比不进入正式实测判定。
