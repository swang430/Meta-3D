## 四、执行细节

### 0. 环境、安全与数据保护

1. 记录现场主机、Git SHA、API/GUI/计算服务实际路径与版本、活动实验室配置、选中测试用例、拓扑 ID/修订、实际绑定的仪器型号/地址/加载驱动、固件、场景文件及摘要、DUT/SIM 与支持频段。不要凭名字或地址认定物理设备。
2. 如需部署：先经现场负责人批准，备份数据库与相关文件，记录恢复步骤并验证可恢复，再按已验证版本组合部署。迁移失败立即停止；不能把旧程序直接对着不兼容的新结构当作回滚。本次代码拉取不自动包含此授权。
3. 核查代理/VPN是否影响仪器网段；仅用受控网络，不向公网暴露 API、默认凭据或数据库。不要用 TCP 连通代替真实设备身份。
4. 在仪器配置保存后核实实际分类驱动，再显式同步实验室绑定。不要整库重新加载掩盖绑定问题。身份序列 `instrument_idn_sweep` 读连接缓存，不是新发身份查询；缺实时身份仍记未知。
5. 对照实际接线逐路核 F64 输出→线缆→PA in/out→线缆→Probe；核极化、衰减/增益、方向、端口编号。SGH 与 VNA/FSVA 若共享一个物理端口，必须明确实际开关或人工换接的互斥方式，不按两条逻辑边认定能同时接通。
6. 原 CAICT 不自动修改。若确需改配置，先导出原始快照/修订与恢复办法，由操作员确认目标后保存新的修订；不改历史执行、校准证书或原始数据。
7. 核急停、互锁、负载/接线额定范围和人员清场。停输出后才能改线；F64 仅一个控制客户端。禁止并行错误队列读取、清状态、运动或维护操作。

预期：设备身份、路线、安全和数据恢复都有责任人确认。任一缺失即停止相应硬件分支。

### 1. V1：只验证今天真正使用的活动路径

入口：调试维护 → 调试序列。

- 执行 `emcenter_switch_health`，分别保存机箱、继电器、互锁信息；错误代码或机箱在线不能证明安全，也不能代替实际切换检查。
- 在确认场景已加载后执行 `propsim_f64_output_level_windows`，记录活动物理输出、映射、合法电平范围与当前值，结束保存错误队列原文。所有功率值取已批准的仪器范围和现场预算，不在此计划指定猜测值。
- 将实际路径与拓扑、场景、开关映射逐一对齐。机箱健康不关闭 P2-9；NEW-1 需同场景成功证据。电平范围不证明 DUT 处功率。

失败处理：保持输出关闭，保存错误原文与配置，先定位地址/绑定/场景/映射哪一层错误；不循环启动、不放宽互锁。

### 2. V2：固定方位、同一次执行的真实诊断

- 使用已保存、服务器接受的 MIMO_OTA LTE 测试用例，DUT 确认支持该频段。核合法统计参数、帧配置、路径、场景资产及安全固定站位；不照搬历史频段。
- 可先用单阶段 precheck 定位前置，但正式闭环必须运行完整测试用例。独立 reference、mimo_test、analysis、report 各自的新执行不能拼成一次验收。
- 记录同一 execution 的配置/路径、Cell ON、Attach、真实吞吐原始值、最终状态、清理与释放结果。缺测不填零，模拟不混入真实判定。
- 若当前服务器允许在校准不完整时进行诊断，只按该既有策略执行并保持 UNKNOWN/N/A；若服务器拒绝，保存原因，不加跳过参数或改模式骗过。

预期：至少一次真实诊断闭环。Attach 失败先核 DUT/SIM、频段、信号路径与真实状态；不把历史已关闭问题重新判为当前缺陷。此步不是正式校准/认证验收。

### 3. V6：停止、释放、面板 Local 与再入

- V2 完成后检查同事务终态与清理原文。STOPPED 不等于已回卷或射频关闭。
- 使用 `propsim_f64_local_handback_check`：release → 操作员先观察设备面板 → confirm 记录观察。断开 socket 不证明面板 Local，confirm 会重新取得上下文。
- 在设备安全与释放确认后，原配置再次完整执行，记录第二个 execution，确认无旧锁/旧会话影响。

失败处理：cleanup 未确认、断链或停止状态不明时禁止自动再入，操作员按厂商批准的安全流程处理并确认。未知写操作不盲目重放。P2-85 与 NEW-2 分别按其证据关闭，CLOSED 仍不代表正式结果有效。

### 4. V3：输入条件与 Cell-ready

- 独占维护窗口，先停止输出，再由操作员建立无输入、缺一路、正常输入三种状态；每次确认安全后运行对应检查。
- 保存同固件、同场景的活动输入、窗口平均/峰值观察及错误原文；比较严格策略拒绝与非严格策略警告是否符合现有实现。
- 同时排除过强输入、错误端口等因素。有限功率读数不能证明 LTE 信号有效。

无法安全换接时记未执行，不带功率拔接，不覆盖保护条件。

### 5. V4：统计窗口与重复性

- 在服务器接受范围内准备 A/B 两个不同统计窗口，除该参数外保持条件一致，逐次完整执行并记录请求值、实际生效值、回执和真实统计窗口。
- 重复性要用相同配置两次。可执行 A→B→A，并用第 1/3 次做 ReportComparison/repeatability；不得用不同窗口的 A/B 证明重复性。
- P1-74 核窗口边界，P1-4 核同配置重复性。阈值取批准的用例/方法；未定义就只给差异，不虚构合格结论。

### 6. V5：运动与返回，条件不齐就不做

- 清场、核机械范围和坐标配置，确认单位确为 degree、偏置准确后，先做批准的小步移动，读取 PFBK/VFBK、确认静止，再做安全返回。
- 使用 `aerotech_positioner_motion_truth`；它不是 HOME。小步成功不能关闭长运动问题 P2-74。
- 有 +90 偏置时，不把 MOVEABS(0)当 HOME。HOME 缺独立批准载体时保持阻塞；P1-79E 的控制器身份资料缺口单独登记。

任何超范围、反馈不明、断链或仍在运动：由操作员执行批准的停止措施，禁止自动补发运动命令。

## 六、现场出现软件故障时如何修

1. 保留原 execution、原始日志、请求/响应、时间、设备面板照片、配置与资产摘要；先安全停止，记录停止是否确认。
2. 分类：配置/接线错误、手册或资格不足、产品缺陷、网络/部署故障。不能把后两类混为“仪器不支持”。
3. 配置错误在确认目标及可恢复后修正，以新 execution 复验；不重写旧结果。
4. 产品缺陷建立最小复现与影响入口/消费者清单，在隔离分支和临时数据库修复，经独立审查、相关回归后提交；共享后端变更按仓库要求安排唯一最终全量责任人。现场用户服务不作测试夹具。
5. 重新部署需版本/数据库备份与恢复方案、现场负责人批准，再完整复验失败场景和停止再入。不能仅因单条命令成功就关闭整项。
6. 无法在安全窗口修复则保留阻塞，写明最小下一动作、责任人和所缺证据。无手册不拼 SCPI，不删除安全门，不把未知补零。
