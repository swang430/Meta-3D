## 2. 现场发现的硬件 / 协议怪癖（已成为驱动设计前提）

- **F64 ATE Server ≠ FS16 SCPI surface**: MMEM 系列指令、`*OPT?`、FTP 全部不可用；F64 用 `-100` 表示"指令不在 firmware"（违反 IEEE 488.2 默认语义）
- **Aerotech 不在 192.168.0.2**: 那是 Manager 软件运行的 PC，转台本身在 .16（MAC OUI `00:11:89` = Aerotech Inc. 验明）
- **Aerotech 是单轴转台**: 没有 Y 轴；驱动原来 hardcode `ENABLE X Y` 一上来就 NAK
- **Aerotech Socket2 idle close**: ~30 秒空闲后远端静默关 TCP，下次命令报 BrokenPipe / EOF（现场实测确认）
- **Aerotech Modbus 路径不可用**: TCP 端口开着，但 register map 是空的，所有功能码都返回 IllegalDataAddress —— ASCII Socket2 才是唯一路径

## 8. 待求证 / 假设（明确标出，未在现场验证）

- **TCP keepalive 加在 Aerotech driver 上的动机** 是 "NAT/firewall 可能静默丢 idle TCP entries"。这是设计假设，**不是现场实测结论**。实测确认的只有 Aerotech Ensemble 自己的 ~30s idle close 行为；网络层是否也丢 idle TCP 没单独测过。OS keepalive 加上是为了"如果网络层也丢、不增加成本"的兜底，不是必要修复。
