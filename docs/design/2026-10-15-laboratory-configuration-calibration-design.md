## 1. 结论与范围

推荐在现有 **LabProfile 统一工作台 + 仪器绑定 + 类型化校准记录 + 执行冻结** 上渐进完善，不另建第二套实验室管理平台。

核心不是“每间实验室都有一张合格证书”，而是回答：

1. 本用例需要什么方法、频率、带宽、极化、空间区域、通道和仪器能力？
2. 选定实验室的物理设备、端口连接、暗室几何及当前加载状态是否满足？
3. 哪些校准覆盖这一次测量，哪些变化需要提醒操作员复核，哪些本来就不适用？
4. 本次实际使用了哪些补偿，它们有没有重复计入，证据能否追溯？

建设顺序建议：**先把配置身份、测量参考面与校准覆盖说清 → 跑通当前暗室最小真实路损闭环 → 冻结与报告同源 → 再扩展场质量、相干方法及多实验室并行。**

### 1.1 本轮设计纳入

- 同一软件适配不同暗室规模、探头/极化、射频拓扑、基站与信道仿真器。
- 当前 CMW500/LTE、UXM/NR、F64/PFS 路线的配置与校准闭环。
- 校准准备、采集、补偿、验证、适用性、失效、复用和报告追溯。
- 非现场软件工作与现场硬件/计量/方法前置条件分开排期。
- 为后续 PWS、TRP/TIS、其他 CE 和多实验室并行保留明确扩展边界。

### 1.2 不纳入默认交付

- 不恢复已拆除的测试计划/执行队列/序列器产品架构；执行仍为 `TestCase → TestExecution`。
- 不新增或猜测 SCPI，不将不同型号的指令、量程、单位、许可条件互相套用。
- 不以 Mock、手工勾选、报告生成或软件内“现场认证”替代计量溯源及外部认证。
- 不把导通/Attach、设备内部对齐、暗室路损、空间场质量当成同一校准。
- 不重新启动 P1-5，不重开已按既有范围关闭的 P0-9；不自动启动 HOLD 的 P2-63/P1-6。

## 3. 先统一概念：六类事实不能混为一个“就绪”

| 事实 | 回答的问题 | 不能证明什么 |
|---|---|---|
| 资源配置 | 保存了哪台仪器、型号、地址、参数和 preset？ | 不证明连接成功、仪器实际生效 |
| HAL 激活 | 当前进程真正加载了哪个 adapter/driver，激活是否成功？ | 不证明 LabProfile 已同步或用例兼容 |
| 实验室绑定 | 本 LabProfile 允许使用哪些资源、暗室与拓扑？ | 不证明校准覆盖，更不证明其他 LabProfile 的设备可并行使用 |
| 配置兼容 | requirements 与 adapter manifest、资产和真实约束是否相容？ | 不证明读数准确、校准有效或测量已完成 |
| 校准适用 | 指定参考面、方法和条件下，哪些实测关系/修正及不确定度可用？ | 不证明 DUT 通过，不自动构成第三方认可 |
| 执行与资格 | 本次冻结配置、实际应用证据、测量与终态能否支撑指定结论？ | 不将诊断完成转换为正式通过 |

计量用语沿用 VIM 2.39：校准建立标准量值及其不确定度与示值之间的关系；**校准、调整和验证不是同一动作**。[S1] 界面可保留厂商“Auto alignment”等原名，但必须注明它对应哪种作用，不以名称推断覆盖范围。

每个用例分别展示：**安全可操作、配置兼容、诊断可运行、校准适用、正式证据资格**。这些是独立判定维度，不是所有测试必经的线性等级。未知安全状态不能因“诊断模式”放行；非安全校准缺口只有在既有诊断策略允许时才能带明确限制执行，正式 KPI 仍为 UNKNOWN/N/A。

## 4. 如何匹配不同实验室

### 4.1 用六个维度描述，而不是只按仪器品牌建模板

| 维度 | 配置内容 | 权威来源/约束 |
|---|---|---|
| 测试方法与范围 | PFS/PWS、MIMO OTA/TRP/TIS、DL/UL、RAT、频段、带宽、层数、判据和标准版次 | TestCase requirements + 经批准的方法范围；名称不参与真假判断 |
| 暗室与几何 | 暗室、可用频率、静区、探头坐标/朝向/极化、DUT 参考点、运动轴与零位 | ChamberConfiguration、几何/坐标记录；设计尺寸与已验证可用范围分列 |
| 物理资源 | 型号、序列号、硬件/软件版、许可、adapter、endpoint | 保存配置 + 权威身份观测；endpoint 不是唯一物理身份 |
| 射频链路 | BS 端口 → CE 输入/输出 → 开关/PA/LNA/双工器 → 探头；反向链路单列 | 服务器拓扑解析、现场接线确认、可用权威回读；不同方向不能默认互易 |
| 信道与测量 | CE 资产/端口映射、load mode、工作点、测量仪器与方法、采样/统计配置 | 冻结资产、manifest、实际操作能力；文件存在不等于该配置可用 |
| 校准与资格 | 校准类型、参考器件、覆盖范围、修正、有效性、审阅与正式资格 | 类型化原始记录 + 共同适用性判定，不从当前模板推导历史证据 |

现有 `type_a/b/c/d/custom` 暗室预置用于减少录入；不作为能力认证。模板只复制结构和建议值，不能复制真实序列号绑定、实测值、校准有效状态或正式资格。

### 4.2 典型实验室适配矩阵

| 配置场景 | 必须具备 | 校准重点 | 当前/扩展边界 |
|---|---|---|---|
| 软件/Mock 实验室 | 结构完整的配置、对应 manifest、真实纯命令拼装路径 | 验证流程、范围匹配和缺证据拒绝，不生成真实校准 | 已有基础；所有模拟结果分账，不允许签发真实证书 |
| 当前 CMW500 + F64 LTE 2×2 PFS | 兼容 LTE profile、真实内部路由、CE 资产、探头/开关/转台、DUT/SIM | 对应频点/极化/逐链路幅度与路损、F64 校准/对齐状态、功率动态范围 | 第一套最小真实闭环；不增加 PFS 相位校准前置 |
| UXM + F64 NR PFS | NR profile、带宽/层数/许可、相应资产及应用证据 | 同样校准下游幅度链；重新验证 BS→CE 上游功率和运行证据 | 不因 F64/暗室相同自动继承 CMW 的 binding 或正式资格 |
| 不同探头数、单/双极化、多环暗室 | 每条所需链均可唯一解析；输出能力与真实探头/极化映射满足 | 完整覆盖所需链、频点、极化和目标区域；禁止靠复制一个平均值补缺路 | 配置模型已有基础；是否适用要逐方法验证，非整数配置检查即可 |
| 无内部 CW 源的 CE | 已确认 passthrough 能力、真实外部 SG、可控隔离路由、合格测量仪器 | 信号源输出参考与全链路测量 | 复用现有 PASSTHROUGH_ONLY 前置；不擅自把基站当校准信号源 |
| 固定布线、缺少校准 SA/参考天线的实验室 | 能说明实际接线、可用安全动作与缺失能力 | 可选经审核的外部测量导入，或补充校准资源 | 不能以“固定布线”绕过当前要求开关隔离的路线；不承诺自动校准 |
| 相干 PWS / 扩展 TRP、TIS | 经批准的方法、完整参考设备与量值链 | PWS 相位/时延/相干性；TRP/TIS 对应上下行功率/接收链 | 独立扩域，不让这些条件倒逼当前 PFS 首通 |
| 多间实验室同时执行 | 设备实例库存、共享关系、跨任务实体资源锁和控制边界 | 各物理路径独立覆盖；共享参考设备有明确调度 | 当前全局每品类单连接不支持此承诺；第一阶段只支持显式选择、串行执行 |

### 4.3 匹配流程与操作结果

1. 选择 LabProfile；未选择且存在多个活动实验室时受控拒绝，不猜测。
2. 解析 TestCase 的有效要求：显式值、服务器解析值及来源分列；当前配置不能覆盖已冻结执行。
3. 对照 manifest 判断声明域，再核实真实设备身份、许可、已保存参数、HAL 与绑定是否一致。
4. 解析本次实际使用的 RF chains、方向、频点/频率区间、带宽、极化、空间区域和功率范围。
5. 由测试方法生成“必要校准 / 条件校准 / 不适用”集合，逐项选择匹配记录并返回原因。
6. 形成可运行范围与阻塞清单；操作员能看到缺哪台设备、哪个端口/频点或哪份证据，而非一个总红灯。

保存配置沿用 P2-83B/C：**保存 → 分类 HAL 激活 → 显式同步 LabProfile**。同步必须确认当前保存快照；失败保留分层状态，不整体 reload 掩盖配置错误。本方案不把跨设备写入、数据库保存与同步包装成一个可回滚事务。

## 5. 配置身份、校准范围与复用

### 5.1 设计选型

| 方案 | 优点 | 问题 | 决策 |
|---|---|---|---|
| A：只整理 UI、继续选一张活动证书 | 改动少 | 不能阻止错频点、错链路、错设备或重复补偿 | 不足以解决核心问题 |
| B：扩展现有模型的范围元信息与共同判定 | 复用现有流程，能逐片闭环 | 需梳理历史记录与所有消费者 | **推荐** |
| C：先建通用设备资产平台、工作流引擎和多 HAL 控制平面 | 未来扩展面广 | 当前需求不要求并行，改动大且产生第二真值 | 仅在确定并行/多实例需求后立项 |

### 5.2 最小数据契约（拟议，不代表现有字段）

不新建“万能校准记录”替代已有类型表。以现有记录为主体，补充版本化范围及证据引用；执行冻结只保存本次必要投影。

| 拟议逻辑对象 | 最小内容 | 归属与边界 |
|---|---|---|
| 配置快照 | Lab/暗室引用、相关设备物理身份、链路及器件、几何、方向/极化、方法版本、影响量值的配置 | 从现有保存配置和 resolver 生成；先局部配置摘要，不立刻新建全项目事件系统 |
| 校准范围 `scope` | 被测量定义/单位/参考面、设备/链路身份、频点或经验证插值域、带宽、功率、极化、空间/环境条件、alignment、输入电平控制/增益及补偿状态 | 附于具体校准记录；不把任意字段塞入备注后由前端解释 |
| 测量证据 | 原始读数/采集配置、设备身份、来源、时间、操作会话、错误与清理结果、参考证书/资产哈希 | 复用已有采集/日志证据；哈希证明完整性，不等于计量溯源或签名 |
| 修正与不确定度 | 原始量、修正值、符号、计算版本、应用位置、预算与覆盖说明 | 不覆盖原始读数；下游按明确测量模型消费 |
| 适用性结果 | 选中记录、覆盖/不覆盖/未知/不适用、缺口理由、要求与记录摘要 | 服务器纯判定；UI/预检/执行/报告同源，不另存可任意写的“已校准”真值 |
| 执行校准快照 | 当次选用记录版本、范围、修正及顺序、实际应用证据、判定规则版本 | 扩展现有 execution freeze 与 `path_loss_application`，不从当前配置补历史 |

配置摘要只包含影响测量和身份的内容；名称、备注、UI 排序不触发物理失效，其他配置摘要变化也只提醒复核，不自动触发校准失效或就绪状态变化。摘要规则需显式版本化，不能给历史对象补新默认值后重新计算并冒充旧摘要。设备序列号缺失时保留未知，不能仅凭相同 IP 或型号认定同一实体。

### 5.3 适用性判定

候选记录必须同时满足：真实可追溯来源、身份匹配、被测量/参考面一致、链路完整、目标工作点和方法在覆盖域内、无已知失效事件、有效性政策满足、修正未重复应用、证据/审核完整。

- `matched`：本次所需范围完整覆盖，仍须确认实际应用成功。
- `out_of_scope`：明确不匹配；不能按“最近一条”顶替。
- `unknown`：元信息或证据不足；不将缺失当默认一致。
- `not_applicable`：测试方法明确不需要该项，附理由；不是操作员跳过按钮。

以上为拟议适用性枚举，不替换已有任务状态和正式 outcome。一个采集任务可以执行成功但测量结果无效，不能把两者合并。

当前路损候选查询含目标频率 ±5% 的匹配规则；这是实现行为，不是已证明的校准精度。目标设计为：精确频点优先；仅在明确记录的插值方法、频段边界、验证误差与不确定度内插值；默认禁止外推。宽带测试还要证明占用频率范围的适用性，不能拿中心频率一个 CW 点宣称整带平坦度合格。

### 5.4 配置变更影响与复用矩阵

配置变化只提醒复核，是否重新校准由操作人员依据变更内容和校准规程判断。系统展示差异及受影响链，不因配置变化本身自动暂停用途、降低就绪状态、使校准失效或强制重校准。下表是操作员复核指引，不是自动执行的失效/重校准规则。证书过期/撤销、缺少本次测试必需数据、安全或配置不兼容等独立规则仍按原判据处理；操作员的复核判断不等于绕过这些规则或授予正式资格。

| 变更或独立有效性事件 | 可复用部分 | 操作员复核关注点／独立规则 |
|---|---|---|
| 改名称、备注 | 原校准全部范围不变时可复用 | 仅记录变更，无物理失效 |
| 改 endpoint，确认仍是同序列号设备 | 不因 IP 改动自动作废所有测量 | HAL/binding/连接及仪器状态；身份未确认时提示复核，不以配置差异自动阻断 |
| CMW 切换 UXM，CE 输出之后物理链不变 | 仅可能复用同频率/带宽/功率/极化覆盖内的下游校准 | 上游 BS→CE、动态范围、工作点、binding、兼容与现场资格；跨频不能直接继承 |
| 换同型号但不同序列号设备 | 未经过该设备的独立链段记录可能保留 | 涉及该设备的源/测量/内部校准及端到端结果 |
| 换 CE 输出口、开关路径、线缆、PA/LNA、探头 | 物理范围未改变的其他链 | 受影响链的幅度/路损；相干方法还含相位/时延，不假定端口等价 |
| 增减探头、改单/双极化或重映射 | 可保留原链原用途记录 | 完整性、极化映射、区域覆盖与所用信道方法；禁止用平均值补新增链 |
| 改频段、带宽或源/接收功率 | 只有已证明覆盖的部分 | 频率响应、动态范围、压缩/噪声底、滤波和 alignment 适用性 |
| 改几何、参考点、探头朝向、静区 | 独立传导段可能保留 | 辐射链、方向图/场质量和坐标关联；不能仅更新距离做理论修正 |
| 改零位/坐标 profile、机械重装 | 纯电缆段可能保留 | 位置相关记录和实际角度/距离；degrees 不能代替 centimeters |
| F64 关机、重新选择 alignment 或改变补偿值 | 原始测量记录仍保留作历史 | Auto alignment 当前有效性、叠加状态及依赖它的校准适用性；见 §7.1 |
| 仪器固件、adapter、算法版本升级 | 不一律删除旧校准 | 由操作员判断变化是否影响量值/解析/应用及是否需复验 |
| 新建/克隆 LabProfile | 可引用相同物理资源的候选记录 | 必须显式证明同一测量范围并确认绑定；不继承“已认证”灯 |
| 证书过期/撤销、环境超界或异常检查失败 | 历史原始数据不删除 | 新执行停止使用相关记录；历史处置见 §9，不回写旧冻结证据 |

不把一个下游校准绑定到整个 LabProfile 的所有无关字段；也不只按 chamber_id 就跨所有拓扑复用。应按**受影响的物理链段与方法范围**判定。

## 6. 校准项目分层：哪些是当前必需，哪些是条件项

| 类别 | 作用 | 当前 PFS MIMO 用途 | 不能替代 |
|---|---|---|---|
| 参考仪器与参考件校准 | 说明 SA/功率计、SG、参考天线/线缆等量值来源和不确定度 | 对采用它们的测量方法是前置；来源可为有资格的外部证书 | 不自动覆盖暗室组合链 |
| 仪器内部校准/对齐 | 保证仪器自身或指定端口组在规定条件下工作 | 按厂商/方法要求检查，不笼统“全部相位对齐必需” | 不等于端到端路损、空间场质量 |
| 传导链幅度/损耗 | 线缆、开关、有源器件等指定参考面之间的关系 | 按最终补偿模型决定单测或包含在端到端测量中 | 不等于空口传播和天线响应 |
| 逐探头/极化辐射链幅度与路损 | 建立已知源与参考位置接收量之间关系 | 当前真实闭环的重点；覆盖实际使用链 | 不等于 DUT 吞吐/RSRP，也不证明整个静区 |
| 相位/群时延/相干性 | 支撑依赖复场相位的测量方法 | **当前 PFS power-only 不设为前置** | 输入流相位补偿不能证明全暗室幅相校准 |
| 探头方向图与极化 | 说明模型使用的辐射/极化响应 | 按方法选择 qualified 厂商数据或合格实测数据 | 不由端到端一个功率点或自动图形拟合生成 |
| 空间场质量/静区 | 对指定区域采样验证均匀性、相关性等适用指标 | 正式方法若要求，必须单独验证；不是首通诊断的全局门 | 中心点路损不等于静区合格 |
| 信道再现验证 | 验证所用 CE/资产/方法的时延、多普勒、相关性等 | 随目标测试方法选择指标与参考 | 不能用输入模型验证自身，也不等于 DUT 性能测试 |
| 系统参考对照与资格 | 参考 DUT/参考报告对照、方法适用与正式证据签收 | 在量值链成立后进行 | 不等于外部 CTIA/认可实验室认证 |

依赖按测试方法产生，不是强制“内部→线缆→开关→相位→天线→静区”全部跑一遍。例如，已覆盖开关、PA、探头和空口的端到端幅度测量，不应再重复应用这些组件的单独损耗。

## 7. 如何实际完成校准

### 7.1 F64 内部状态、Auto alignment、User alignment

手册已核实的事实见 [S3]：

- User alignment 按频率、物理端口和带宽关联参数；加载仿真与改变频率会影响所用参数（§11.1、§11.3.1–2，印刷页 165–166）。不能只记一个文件名。
- 在 User alignment 开启时完成 Auto alignment，正确使用需要保持两者一起开启，参数会相加（§11.3.3，页 166）。软件补偿必须知道这层叠加。
- Auto alignment 在仿真器关机后失效；仿真所用频率/端口必须被 alignment 覆盖（§17.5–17.5.1，页 199–200）。不能用“未到证书过期日”放行。
- In/Out loss 可表示仪器外部连接链的损耗（§4.3.4，页 72）；应用它们会改变功率解释所用参考关系，必须与软件的链路修正分别登记。

方法还须冻结影响量值的输入电平控制/增益模式、衰落及输出状态。手册 §4.3.4（页 72–74）区分不同自动输入电平控制行为；不能将在一种增益状态下测得的关系未经核验直接用于另一种状态。CW 校准和正式衰落测量之间如何转换，由方法明确，不默认二者完全等价。

实施策略：先读取和记录本次真实状态、兼容范围及原始证据；需要厂商调整时走已核手册的受控流程或人工向导。**本设计不提供新 SCPI**，现有 API 返回空串/不可解析/不支持时保持 unknown，不能转换为“未启用所以通过”。

F64 外部信号输入相位校准应用说明仅证明 BSE 输入流之间的相位差测量与补偿（[S4] §1，页 4），不证明探头、空间或参考接收链全部校准。NotebookLM 对这一部分的扩大解释不采用，以本地原文为准。

### 7.2 当前最小真实闭环：逐链路幅度/路损

沿用现有 CE+SA 路线，不平行新造测量服务：

```text
已知且可追溯的源/CE 输出参考面
  → 指定 CE 输出 → 指定开关/有源链 → 指定探头/极化
  → 暗室参考位置 → 参考天线 → 接收线缆 → 合格 SA 功率读数
```

**准备**：冻结 LabProfile、方法、逐链路拓扑、频点/带宽/功率、参考位置及环境条件；核实 SA 的标量功率测量定义、源输出依据、参考天线证书、接收线缆修正及设备额定限制。数值/容差来自方法负责人批准的规程或对应手册，不在代码里猜一个统一值。

**资源选择**：

- CE 支持已确认的内部 CW 生成时复用 `INTERNAL_CW_GENERATOR` 路径。
- 只有 `PASSTHROUGH_ONLY` 时，复用真实外部 SG 和真实可控隔离路由；当前代码要求的 rfSwitch/route_target 不能省略。
- 缺参考天线、可信标量读数、可控安全路由或源输出依据时，显示缺口并停止该校准；不是用 Mock 自动补齐。

**操作步骤**：

1. 审查连接图与功率上限，放置/记录参考天线位置和姿态，确认非目标链处于规定安全状态。
2. 获取共同仪器 lease，核实真实身份和当前配置摘要；执行前发现变化则返回冲突，不带旧参数继续。
3. 应用所需 route、源、接收配置，消费错误队列、失败返回和有效回读；“写入完成”不等于“应用成功”。
4. 按批准的稳定时间、重复数、频点、极化与每条链采集；保存原始样本，不把失败/缺测值当 0 参加均值。
5. 按版本化测量模型计算量值、修正与不确定度；记录所有已启用仪器内/外部修正。
6. 应用拟合/修正后做独立检查：保留未参与拟合的检查点、参考连接或复测数据，不能用拟合自身的输入证明自身精度。
7. 停输出、恢复规定安全状态并归还控制权；保存清理证据。清理未知/失败进入硬件异常处理，不能只把任务显示为成功。
8. 审阅完整性、覆盖、误差及不确定度；合格后才把候选记录用于后续正式选择。局部失败只允许明确子范围使用，不生成全域绿色状态。

对宽带/多载波测量，CW 幅度校准的适用性须另行论证频响、滤波/统计口径及功率范围；既有多频服务可复用，但不能自动证明任意宽带信号校准完成。

### 7.3 参考面和补偿账目：先定义量，再谈修正

当前 `_real_path_loss_measurement_via_ce_sa` 实际使用：

```text
path_loss = CE 请求功率 - SA 平均接收功率
            + 参考天线增益 + 探头增益 - 参考天线到 SA 线缆损耗
返回 abs(path_loss)，uncertainty = 样本标准差 + 0.3 dB
```

这只是代码现状，**不能直接解释为任意参考面的可溯源净损耗及完整不确定度**。CE 请求功率也不自动等于真实输出功率。后续必须一次列全所有补偿消费端，再确定旧 `path_loss_db` 的量值含义与迁移方式。

拟议先区分两类量：

- **端到端净传输量**：包括实际路径中开关、PA/LNA、探头与空间的总效应；若要输出相对各向同性参考的等效接收功率，可在方法适用且参考天线/线缆有依据时采用 `P_ref_eq = P_SA + L_rx_cable - G_ref`，再定义 `L_net = P_CE_out_ref - P_ref_eq`。这里的功率均为明确定义的同类量，增益/损耗为相应频率和极化的修正。它不是 DUT 天线端口实际功率。
- **去嵌后的传播量或链段量**：按另一个明确模型去除探头/有源器件等效应，量名、参考面、公式版本和后续补偿必须对应；不能与上项混用。

以上是拟议测量模型，不是新驱动回读单位声明；须经计量/测试负责人裁决后实现。保留带符号传输量，有源链净增益不能取绝对值变成损耗。禁止静默修改旧记录含义或按新公式重写历史结果。

每次应用一张账目表：`链段/效应、原始值、修正值与来源、已在F64应用、将在软件应用、实际应用证据、未确认原因`。同一项只能在指定位置补偿一次。F64 输出设定、F64 输入观测、参考 SA 测量、DUT RSRP/吞吐是不同量，报告不得把其中一个重命名成另一个。

### 7.4 不确定度与判定

预算按测量模型建立，至少审查：源/接收仪器证书、参考天线增益与失配、线缆修正、开关重复性、位置/极化误差、环境漂移、重复采样及插值贡献。已有固定 `+0.3 dB` 不是完整预算的依据。

按 GUM 对输入贡献、灵敏系数及相关性合成：`u_c² = Σ(c_i²u_i²) + 2Σ(i<j)(c_i c_j cov_ij)`；需要扩展不确定度时说明 `U = k·u_c` 的 k 与覆盖依据，不默认独立，也不把 k=2 无条件写作 95%。[S2]

合格阈值、保护带/判定规则由对应测试方法批准；没有阈值可以保留测量结果，不能写“校准合格”。有效期也按参考证书、厂商条件、实验室稳定性与事件政策制定，不能将当前编排中的 90/180/365 天当通用计量标准。

### 7.5 条件校准与方法验证

**相位/PWS**：当前 PFS 不需要探头相位校准，既有启动口已拒绝；外部相位 CSV 导入仍有其来源契约。未来 PWS 单独定义相干参考、相位/时延/温漂、全链硬件与算法，不能仅恢复按钮就称可用。

**方向图/极化**：复用 `probe_pattern` 共同消费者。qualified 厂商方向图与现场测量分别管理；现场测量需明确参考/被测天线口径、远场或经过验证的近远场转换、权威标量功率、坐标/极化与校准链。不得用理论方向图校准出一张“实测方向图”再验证同一模型，形成自证循环。P2-32B 仍受这些前置约束。

**静区/QZ**：真实网格需经过验证的线性位移/定位测量系统及采样方法。现有角度转台不能充当厘米 XY 扫描器；代码在真网格采集前拒绝。激活时必须同步 `quiet_zone_calibration_truth` 与详情/历史/状态/报告，不能只增加真实写入而读取仍按 legacy 处理。

**时延/多普勒/相关性**：FSVA 已有真实 IQ 采集，但 `RealRsFsvaDriver.measure_pdp` 当前计算的是接收信号的时延自相关代理，源码明确不是真 PDP。它可以保留为如实命名的工程诊断，不能仅因有真实 IQ 就签收标准 PDP；标准化验证需已知激励、独立参考、同步/估计方法与不确定度。其他 SA adapter 未实现的方法保持不可用，不能凭同为频谱仪替换。

**TRP/TIS、上下行与双向链**：按对应方法增加接收/发射参考与动态范围验证；PA、LNA、双工器条件项不能自动假定互易。现有通用证书的 TRP/TIS 等字段也不代表它覆盖所有 MIMO 场景。

**RT 与标准对照**：数值信道统计符合目标模型、硬件再现所加载信道、DUT 在该信道下的性能是三份证据。沿用三个月计划中的 R01～R04、C01～C04 分账，不以一个软件 golden 或参考报告替代真实全链测量。

## 8. 受控执行、并发与失败处理

复用现有校准作业、仪器 lease、错误消费和冻结机制，不新建通用工作流引擎。方法配方描述必要资源与操作顺序，不恢复已拆除的产品执行队列。

```text
只读范围评估 → 操作员确认接线/风险 → 获取所需仪器 lease
→ 重新核验配置/身份 → 原始采集 → 修正计算 → 独立验证
→ 安全清理及控制权归还 → 审阅范围结果 → 供后续执行选用
```

- 现有 `InstrumentTestLease` 为进程内控制机制，退出不等于已安全停机；调用方必须负责并记录安全动作。第一阶段保持串行作业，不允许多 API worker 各自认为已独占硬件。
- 不在长时间硬件 I/O 中持有数据库事务锁。冻结后用现有并发控制核实摘要，结果写回时发现漂移则受控拒绝激活，不声称数据库能撤回已发射的 RF。
- 执行中任何校准配置/手动接线改变需要终止当前有效采集，重建快照；仅暂停等待人工观察，不代表允许修改后继续沿用原证据。
- 异常、设备拒绝、超时、取消都必须消费失败信号并尝试规定清理；无法确认安全状态就隔离后续任务，提示人工处置。
- 重试新建测量尝试并保留前一次失败；不把不同接线/仪器会话的样本拼成一次“完整校准”。

## 9. 历史数据、失效与报告

### 9.1 迁移与发布

1. 先只读盘点真实记录分布：类型、来源、有效状态、频点、链路、证书关系及消费端，不按 JSON 形状将所有历史记录宣布作废。
2. 新字段/版本以增量方式加入；旧摘要按旧原始 payload 验证。历史缺少范围的记录仍可审计，但不能自动扩为新范围。
3. 可由已有可核证据补登记元信息时，保留来源、登记人、变更记录；不可从当前 LabProfile 反推过去接线或重新给历史赋予真实来源。
4. 对存量真实结果逐类给出“仍覆盖 / 仅原已知范围 / 范围待核”，再发布新门与消费方；不能在没有数据盘点时一刀切，也不能为兼容全量放行。
5. 测量模型更改须新版本与明确迁移/重测策略；旧数据不就地按新公式改算，新旧对照留痕。

### 9.2 失效政策

配置变更只触发差异提醒与操作员复核，不自动使记录失效或改变就绪状态；是否重新校准由操作人员判断。超期、已证实的厂家状态失效、参考证书撤销、异常检查或环境超界，仍按对应独立规则停止新执行使用受影响记录。仅某条链按独立规则失效不自动删除其他链，但方法要求集合不完整时本次正式测试不得通过。

执行报告保留当次冻结的证据与当时结论，不因后来 LabProfile 编辑而改变。当出现撤销或已知计量缺陷时，应在历史读取/下载处展示独立的撤销/影响评估状态，必要时阻止继续作为有效正式报告交付；原文件和原始证据保留，不静默重写历史。具体追溯范围由质量负责人依据证据决定。

### 9.3 报告内容

复用现有“测试仪器配置”“本次测试参数”章节，增加校准子节，至少列出：

- 实际实验室/暗室、物理仪器身份与所用链路；请求、服务器解析、确认应用值分列。
- 校准记录/版本/方法、频点/带宽/功率/极化/参考面和空间覆盖。
- 原始测量、修正值、应用位置与顺序、不确定度、证书/原始证据引用。
- 本次未应用/未确认/不适用的项及原因；过期、撤销影响或 legacy 限制。
- 诊断与模拟说明、正式资格及测量结论；有报告不等于正式 PASS。

所有内容来自本次执行快照和适用的证据状态，不用最新 TestCase、当前仪器配置或当前活动证书补真。生成、列表、详情、重建、下载与历史路径须共同处理，不只修 PDF 模板。

## 10. 操作员工作台设计

在现有 LabWorkspace 下增加“校准与资格”视图，或在总览内进入同一模块，具体导航由 UI 片确定；不再让操作员分别猜四个页面的数据是否同步。

**总览**：实验室身份、保存/HAL/binding 三态、当前用例/方法要求、逐项校准覆盖和安全缺口。未选用例时只展示设备/校准库存，不能声称“所有用例兼容”。

**配置变更**：保存前预览会影响的链路和记录；保存后执行既有分类激活；显式同步时显示新旧快照与影响。差异标签只表示“有变化，待操作员复核”或“无配置差异”，不自动生成“校准需重测”结论；重校准决策由操作员作出，无差异也不证明校准有效。

**校准工作单**：展示接线图、所需设备/证书、频点/链/极化、参考面、功率限制、预计步骤与未满足前置；只提供当前真实实现的动作。缺失能力提示原因，不显示假可执行按钮。

**采集与人工协作**：明确当前步骤、仪器、实际功率/状态及来源；提供受控暂停、取消和清理反馈。人工确认接线与阅读警告不能单独升级测量 provenance。

**结果与应用**：原始记录、计算版本、独立检查、覆盖范围及修正账目可查看；审阅后选用与实际应用回执分开。不允许一个“设为有效”按钮绕过机器校验。

## 12. 验收场景与实现前必须列全的消费端

### 12.1 最小验收场景

| 场景 | 应有结果 |
|---|---|
| 同一物理链、同一范围，重复执行 | 选择同一有效记录并冻结；实际应用仍取得本次回执，不复制上次回执 |
| CMW 换 UXM，仅下游保持不变 | 分段判断复用；新 binding/上游/工作点/资格未满足前不整体绿 |
| 两个 LabProfile 同名或共享部分设备 | 按 ID 和物理资源判定；当前控制边界内串行，不能因不同 Lab ID 绕过独占 |
| 单链端口或极化改动 | 只标受影响范围；缺少本次必需链时拒绝正式放行 |
| 只有一个频点校准，运行宽带或另频段 | 无已批准覆盖/插值证据则 out_of_scope/unknown，不按 ±5% 默许 |
| F64 重启或两层 alignment 叠加发生变化 | 重核当前有效性和补偿账目，不能沿用旧“有效”灯 |
| Mock、手工输入、历史缺范围或读取失败 | 保留来源和原因；不转换 0、不进入正式 KPI、不补造证据 |
| 采集成功但误差超限/取消后清理失败 | 任务状态、测量有效性与硬件安全分别显示，不能假成功 |
| 冻结后编辑 TestCase/LabProfile/证书 | 当次快照不变；执行中影响硬件的漂移受控拒绝；报告不读取新配置补旧值 |
| 历史证书撤销 | 保留原始记录与当时结论，另显撤销影响；不得无提示继续作为有效正式报告交付 |
| PFS 未做相位校准 | 不增加无关前置；若改为 PWS 则因方法/能力未获证明受控拒绝 |
| 真实 IQ 有波形但只完成自相关算法 | 如实诊断展示，不输出“标准 PDP 已验证” |
