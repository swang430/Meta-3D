# PC-04A：开关不动，自动采集整条路径的功率与损耗

## 状态

## 1. 用户实际怎么操作

1. 在实验室配置中选择一条链。服务器从已有配置取得 F64 输出口、开关通路、探头及极化、仪器连接；界面展示供核对，不再让操作员重复输入已有配置。
2. 确认参考天线及位置、接收线缆资料、测量频率和允许的发射功率；已有资料自动带出，缺失才要求补齐。接收线缆数据必须覆盖本频率，不用拓扑中其它线段的损耗替代。
3. 操作员确认现场接线和开关已经固定到所选通路，使用已准备好的专用校准仿真。系统不自动切开关、不移动转台、不换接线、不启用已停用仪器。
4. 点击“开始采集”：系统设置校准单音，自动读取 F64 输出口实际功率和信号分析仪输入口功率，重复采样并计算整条路径的损耗或增益。两端读数不允许由请求体手工提供。
5. 完成或取消后，系统停止本次单音，显示停止是否确认，并保存原始回复、计算过程和未确认项。可查看历史记录；不因采集完成就自动选用补偿或签发校准资格。

原 PC-02A 人工计算只保留为明确标注的“人工参考值计算”，不能成为自动采集失败后的替代成功路径。PC-03A 继续只读记录状态，不承担功率测量。

## 2. 直接采用的测量方法

路径仍为：F64 物理输出口 → 固定射频开关 → 功放和线缆 → 发射探头 → 空气 → 参考天线端口。
参考天线到分析仪的接收线缆另作一次修正。

`整条路径损耗 = F64 输出口实测功率 −（分析仪输入口实测功率 + 接收线缆损耗）`

单位分别为 dBm、dBm、dB，结果为 dB；正值表示损耗，负值表示增益，不取绝对值，不再加减功放或天线标称增益。请求的发射功率与实际测得的输出功率分列，不能相互代替。

首批只支持已核对的 F64 内置单音与 FSVA3000 标量功率测量。不自动回退到信号源透传、VNA 或其它型号。一次只采一条固定链，可在明确确认后逐个测量频点；不声称一条链或一个频点覆盖全部实验室配置。

## 3. 测量前和测量中的条件

- 服务器核对所选实验室、链、F64和分析仪的保存配置、已加载驱动及实际身份。配置盘点的声明不当成实物回读；接收线缆和参考天线仍记录操作员确认的来源。
- 首批要求已准备好的专用校准仿真处于实际 RUNNING 状态，确认本输出口没有其它混入信号。系统不擅自加载或启动未知仿真，以免其它输出口同时发射。未满足时告诉操作员具体准备项，不把旧缓存当新测量。
- 读取实际状态，不只信驱动 `_emulation_running` 缓存。测量前后均核对状态；STOPPED时输出功率可能是最后运行值，必须拒绝本次计算。
- 对单音设置的失败返回、异常、错误队列、超时分别消费；写入完成不等于设置生效。保护频率、端口及功率条件在首个写命令前检查；缺少安全依据时不发射。
- 单音设置后至少跨过厂商0.5秒测量窗口再取数；`not ready`仅有限次重试。每组保留源端前后读数与接收端读数、采样时间及原始回复，不声称两台仪器硬件同步；不把无时间戳的设备回复伪装成设备内部采样时间。
- 持有同一次实验的仪器控制权，关闭会干扰错误队列归属的后台监控；F64单连接与分析仪事务锁保护完整设置/读取操作。采集中不切换仪器、链或补读当前配置。
- 暂无接收线缆资料时可以显示已采到的功率和缺项，但损耗为空；不能拿0或功率设定值补齐。非有限数、单位未知、测量未结束或错误回复不能参与计算。

## 4. 保存什么、如何判断结果

复用 `DiagnosticRun.sequence_evidence` 的既有 `SequenceEvidence` 格式，完整版本化采集记录保存在 `extra.fixed_route_acquisition`，同时支持专用采集历史及共享诊断列表/详情。共享列表中未获校准资格保持未判定，模拟不显示正式通过。不写旧 `ProbePathLossCalibration.path_loss_db`，不创建第二套校准引擎。

记录至少包含：

- 采集编号、实验室/模式/链/极化、当时配置快照及摘要、固定开关通路声明；
- F64和分析仪实际身份、连接及驱动、物理端口、参考天线位置、接收线缆数据来源和适用频率；
- 请求设置值、实际回读、逐次样本、原始回复及错误、主机时间、测量单位/带宽/状态、F64对齐及补偿状态；
- 计算方法版本、各项修正、带符号的损耗结果、重复采样离散程度；独立复测另存一条记录并关联，不把同次重复采样称为独立验证；
- 成功、失败、取消、清理未确认分别显示。停止失败时即使已有样本，也不得显示“校准成功”；保留部分记录并突出“可能仍在发射”。

“已采集”只表示本次软件流程取得所述证据，不表示符合计量要求。参考件证书、仪器绝对准确度、不确定度分量及覆盖条件不足时显式列缺项；不复用旧 `标准差 + 0.3` 常数冒充预算。本片不授予正式校准资格，不影响就绪，不自动把记录应用到测试；PC-04B验证实际量值，PC-05负责适用性、执行冻结及补偿接入。

历史读取只用当时记录，不从现配置或当前仪器补齐。畸形/缺损历史明确标记不完整；Mock只验证流程，标模拟、不填真实功率、不产生正式损耗。

## 5. 取消和清理不能等未来工作台

现有路损API虽然返回任务编号，实际在请求中同步完成，未找到可直接复用的取消作业接口；不能在计划中虚构它已存在。
PC-04A包含必要的“开始、进度、取消、历史”入口，复用既有服务、控制权与审计记录。只增加单次采集所需的本进程任务与取消信号，不搭通用调度平台。

取消按“停止请求 → 当前有界I/O结束 → 停止本次单音 → 保存结果 → 归还控制权”执行。
浏览器取消请求不等于仪器已经停止；关闭页面不清除后台采集或审计。服务重启后的未终结记录显示中断/停止未确认，不自动续跑，也不声称重启已关闭射频。首批部署限定单API进程；实现前核对启动方式，不在多进程间假共享内存任务。

只清理本次创建的单音，不关闭其它执行的仪器；失败仍调用已有安全清理。停止布尔返回和异常都进入最终记录，不能只写日志。射频开关在成功、失败、取消四种情况下均不发切换命令。
