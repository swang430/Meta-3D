# 本批聚簇表能提供哪些 GCM 输入

在仓库根目录执行以下命令。核查直接读取原始压缩包、六组簇表与质量表；校验值来自同一批次已归档的逐帧评估。输出路径须尚未存在。

```sh
api-service/.venv/bin/python -m scripts.s5_evaluation.gcm_audit \
  ~/.codex/artifacts/2026-11-11-s5-mpdb/original.zip \
  --coordinate-units metres --speed-m-s 5 \
  --s5c-exports ./基站仿真项目_2026-11-11_20_35_46_CDL聚簇 \
  --output /tmp/gcm-real-input-audit.json
```

上下行各有 38 条链路。每个方向，8、16、24 簇表分别有 304、608、912 行；六份质量表均逐帧对应原始路径数和该帧簇数。输出逐文件列出实际字段和 SHA256。簇表给出时延、功率损耗、相位、四个中心角、多普勒和传播类型；质量表给出数量和评分。两类表均未记录每条原始射线归属的最终簇、各簇角度扩展或持续到下一帧的簇编号。同帧行号、数量相符和质量评分都不足以恢复这些信息。保留原簇所需的补件是同次导出的成员对应表或直接计算的角度扩展，以及独立的跨帧身份依据。

按《Channel Studio GCM User Guide》Revision 15 第 13 章第 81 页，CLUSTER/PATH 文件导入仅接受上下行中心频率相同的 TDD 工作点。底层白名单解析器先检查载频必需列、单频及上下行一致性；缺失或不匹配时工具输出不可证实报告并退出2，不编造逐帧值。通过解析后，工具在原始 MPDB 中按帧号复核两端中心频率并记录实际范围。本批 38 对均为 2.4 GHz。该检查只核实频率条件。厂商导入文件示例在 GCM 安装目录的 Samples 文件夹，实际导入与播放仍需单独验证。

## 直射径能否占用 GCM 编号 0

Lauraycs 源码版本 `a09967ecb` 的 `webService/app/services/channel_analysis/analysis.py::_has_direct_path` 在同一链路的原始路径中查找 `CHANNEL_TYPE == 0`。本批生成器版本未能从压缩包确认，因此这里按该版本解释为直射候选。按方向与 LINK_ID 分组后，8、16、24 簇六组各自均有 35 帧零候选、3 帧一个候选、0 帧多个候选。原始射线与各档簇表的类型 0 计数逐帧一致。例如下行 LINK_ID=0 有一条原始类型 0 射线，三份导出表各有一条类型 0 记录；上行 LINK_ID=3 原径和三档导出均为零。结果 JSON 的 los_candidates 给出逐链路计数。

GCM 手册 §13.2.5、表 14‑5 将编号 0 留给直射径。写入该编号前，须确认本批生成版本的类型约定、导出记录确实代表同一条直射径，以及该位置只有一个可对应的直射候选。计数相符不能证明成员归属。缺候选不得凭最强簇补号，多个候选也不能凭行序挑选。工具保留未确认的编号。
