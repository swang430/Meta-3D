# P2-25 日志分类与历史搜索设计

## 可观察故障

“数据归档与报告 → 系统日志”的文件下拉框把当前日志、按天归档日志和
`exec-<execution_id>.log` 混在同一份平铺列表中。文件数量增加后，操作员无法先按用途
缩小范围；历史执行日志又只能凭 execution ID 猜文件，不能按发生时间或文件名定位。

## 已批准交互

界面先分为“当前日志”和“历史日志”两种模式：

- 当前日志只显示后端标记 `is_current=true` 的文件，使用中文业务名称并保留原文件名；
  当前模式继续允许自动刷新。
- 历史日志再分为“分类日志”和“执行日志”。进入历史模式立即关闭自动刷新，避免对不再
  变化的归档文件持续轮询。
- 历史分类日志按“日期 · 中文分类 · 原文件名 · 大小”显示。
- 历史执行日志按“最后修改时间 · 执行 ID · 原文件名 · 大小”显示。
- 两种历史下拉均可搜索。可搜索文本直接包含日期/时间、中文分类、完整文件名和完整
  execution ID，因此 Mantine `Select` 的现有本地搜索即可满足需求，不新增服务器搜索协议。

## 分类真值

后端 `/system-logs/files` 已提供 `filename`、`last_modified`、`size_human` 和 `is_current`，
本片不扩 API：

1. `is_current=true` → 当前日志；
2. 非当前且文件名匹配 `exec-*.log` → 历史执行日志；
3. 其余 `.log` 归档 → 历史分类日志。

分类日志中文名称由文件基名映射：应用、审计、数据库、前端、SCPI、信道引擎、测量、
校准、告警；未知基名保留原文件名，不猜测含义。归档日期优先取文件名中的
`YYYY-MM-DD`，没有日期后缀时用 `last_modified`，所以 `.1` 轮转文件仍然可检索。

## 状态与失败策略

- 切换模式或历史子类时，选择该分组的第一个文件；没有文件时显示空态，不偷偷回落到
  另一分组。
- 选择历史文件时强制 `refreshInterval='0'`；历史模式的自动刷新入口禁用，手动刷新、
  内容过滤、分页、下载和导出继续沿用现有路径。
- 文件刷新后若当前选择已不存在，只在当前可见分组内重新选择，禁止跨组静默跳转。
- 从执行历史“一键看日志”仍进入当前 `app.log` 并使用 execution filter；如当前文件无匹配，
  操作员可切历史执行日志并按时间或 ID 搜索。

## 验证边界

- 纯 TypeScript 行为测试锁住三类分组、中文标签、日期回退和 execution ID 搜索文本。
- 组件接线测试锁住当前/历史控件和历史模式关闭自动刷新。
- mock 文件列表同时提供当前、分类归档、执行归档三类数据。
- GUI production build 与既有 G14/G15 日志规则门必须保持绿色。
