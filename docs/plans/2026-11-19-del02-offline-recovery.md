# DEL-02 升级失败回退与恢复核验

2026-11-19，使用独立 Docker 内部网络、PostgreSQL 14.20 临时内存卷、随机密码和合成证书记录。未连接客户库，未使用既有数据库容器、卷、配置、证书或备份目录。

| 实际操作 | 核验结果 |
|---|---|
| 以旧版 2b5de140 构建镜像并建立旧版表结构。仅在首次创建空库时只读挂入 #587 已修复的历史建约束迁移 | 旧版迁移号 c4d6e8f01234。首次试用新版模型建历史库时发现其已提前包含新字段，弃用该试验结果，重新用旧版源码和新空库建基线 |
| 在旧库创建一条明确标为演练的证书记录及对应外部附件，停写后用交付脚本导出，另存实例配置、校准数据目录和证书目录 | 生成一份有效数据库归档。随后指定不存在的演练库，备份退出失败，未发布空备份，已有有效归档保留 |
| 在独立数据库事务锁住最后一张待改表，为候选升级设置 700 毫秒锁等待上限，再从候选镜像正常入口运行迁移 | 实际数据库报告锁超时，升级进程非零退出。旧迁移号保留，四张表均未留下新字段 |
| 在另一空库运行 pg_restore --single-transaction --exit-on-error；外部文件恢复到新目录，再启动原版镜像 | 证书整行与备份前一致，由该行定位的附件字节一致。配置及校准文件逐文件比对一致，配置文件权限 0600，旧版健康接口返回 200 |
| 在恢复库和恢复目录上重新启动候选镜像 | 迁移到 d5e7f9012345，健康接口返回 200，证书整行和关联附件保留。原演练库仍为旧迁移号 |
| 以实际 Compose 文件解析新库配置，独立名称、临时卷和随机宿主端口运行同一 PostgreSQL 镜像 | 缺少密码时 Compose 拒绝生成配置。宿主端口仅绑定 127.0.0.1；宿主通过 TCP 使用显式密码可连接，缺少密码被拒绝。已有卷的角色密码须由数据库管理员另行轮换 |
| 启动主机模式 API 与计算服务，读取实际监听地址；启动界面开发服务 | API 127.0.0.1:8000、计算服务 127.0.0.1:8001（模拟启动，用于核对访问范围），两者健康接口均返回 200。界面本机监听 ::1。容器服务模式仍需由部署者显式限制宿主发布地址及容器网络 |
| 在无网络的候选镜像启用 AUTH_MODE=required；另在未设置 JWT 签名密钥时调用令牌接口 | 当前业务路由没有统一应用鉴权，要求该模式时启动明确失败。没有配置本站密钥时拒绝签发，验签不返回有效身份 |

操作步骤见[恢复指南](../guides/database-backup-restore.md)。数据库归档不包含文件系统。每个站点需按自己的挂载清单备份配置、文件与密钥，并核对相互引用。

此次离线证据只覆盖上述旧版到当前版本、合成业务数据及部署默认值。客户真实历史数据、认证网关、容器网络成员、站点防火墙和实际停机切换仍需在目标环境检查。回环绑定允许本机进程访问服务，不提供用户身份认证。
