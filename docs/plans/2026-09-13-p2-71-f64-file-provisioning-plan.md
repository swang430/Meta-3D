# P2-71 F64 文件常态化提供与版本控制调研计划

**目标**：回答现有 CAICT F64 的 `.smu` 如何被提供和识别版本；把厂商手册能力、该机现场能力、当前软件能力分开，不把调研结果误写成已实现的自动部署或正式设备字节证明。

**边界**：本片只改现势文档和准确性注释。不发送仪器命令，不改 SCPI、HAL、Readiness、执行冻结、MEASURE、报告、正式 provenance 或数据库。P1-78 对 SMB 正式运行依赖的移除不得回退。没有现场设备时，现场半保持开放。

## Task 1：列出全链和证据等级

1. 从 `Propsim User Reference` Rev 10.2 的 §20.4.3、§20.4.13、§20.4.14，`Propsim ATE environment and practices AN` Rev 2.2 的 §1.1/§2.2，以及 `PROPSIM F64 Quick Guide` Rev 3.4 的 System 菜单逐项核对：文件放置、列举、传输、取回、加载、当前身份、容量、删除和会话约束。
2. 用现有 `propsim_f64_health`、现场简报、`test_f64_channel_model_listing` 核对 CAICT F8800A 的已观察能力；手册命令存在不等于当前固件可用。
3. 枚举当前 `ChannelAsset` → 冻结 → resolver → F64 加载 → operation receipt → P2-66 消费链，明确每个 digest 和回读究竟证明什么。NotebookLM 只用于定位原文，所有肯定断言回到原厂章节核验。

## Task 2：做有界决策并登记现场门

1. 比较厂商推荐的本地 `D:\User Emulations`、网络共享/可移动介质、手册 `MMEM`、当前关闭的 FTP、开发用 SMB。不得从通用 PROPSIM 手册推断这台 F64 的 `MMEM:DATA` 可写。
2. 决定当前运行保持已登记的仪器侧路径与现有 SCPI 加载证据；版本与字节同一性保持操作员声明/待核，不新增设备 attestation。列出“若要自动化发布，先取得什么现场证据、如何保守回滚”的下一片准入门。
3. 现场可在独占维护窗口复用已有 `propsim_f64_health` 的 `MMEM_CDIR/CAT` **支持分类**；该序列发送 `*CLS`、消耗错误队列，不保留查询原始回复，绝非无副作用的只读文件核验。原始回复捕获和文件取回、写入、替换与摘要验证均须先有另行设计的受控诊断载体，不能现场临时尝试。

## Task 3：同步当前声明并验约

1. 新增 P2-71 调研结论文档；更新 roadmap 的 P2-71 状态、当前焦点、现场 blocker 与误导性的现势摘要，不篡改历史现场记录和旧设计稿。
2. 仅纠正当前代码注释中“所有 F64 都无 MMEM”的过宽说法为“CAICT 该机已测查询不支持；通用新版手册有命令，不能推广”。不改变生产行为。
3. 独立核对每项事实的源章节/代码位置；运行文档链接与 `git diff --check`，针对修改过的注释运行相关定点测试；做一次 fresh 只读功能/事实内审。推送 Ready PR，依仓库 R1→R2 规则收口并合并、同步 `main`、清理工作树。
