# 工作台逐帧轨迹计算与下载

进入“信道工作台”，在“从原始文件导入轨迹”选择方向、原始 MPDB 压缩包、该方向的聚簇 CSV 和质量 CSV。本次交付速度为 5 米/秒，选择以米解释坐标后生成交换文件。可下载该文件，也可直接点击“计算逐帧模型频响”，查看表格并下载全部原始时刻的计算结果。支持重新打开已下载的交换 JSON。

导入服务读取 ZIP 的上下行记录、原始路径数量和位置，根据指定速度推导各帧时刻。转换前核对 ZIP 与该方向两个 CSV 的 SHA256，并校验帧覆盖、实际簇数和质量表。当前文件组及校验记录见 [S5c 逐帧评估](s5c-24-frames.json)。这一批每帧实有 24 簇。生成软件版本未知，原始查询没有显式给出预算。交换文件将原始请求预算保留为未知，每帧另存实际簇数。新的 8、16、24 簇导出均可通过自身清单导入，物理适用性保持未知。

计算服务通过 CHANNEL_ENGINE_PATH 使用 ChannelEgine 的 synthesize_sampled_trajectory。每个输入时刻产生一行复频响，缺测帧保留原因。频偏依次为 −5、−2.5、0、2.5、5 MHz，复数实部和虚部按此顺序对应。下载 JSON 保存原始数值精度。

## 新导出批次的清单

工作台同时选择该方向的配套清单。文件提供者应在交付时记录原始 ZIP、同名聚簇 CSV 和质量 CSV 的 SHA256，每个方向各一份。以下为字段示例，校验值请填写对应文件的实际 64 位十六进制摘要。请求预算有来源时填 1 至 24 的整数，缺失时填 null。服务独立核对每个文件当前内容、帧身份、原始路径数和实际簇数。内容校验只证明所用文件与清单一致。

```json
{"schemaVersion":"meta3d-cluster-delivery/1","direction":"downlink","requestedClusterCount":null,"inputSha256":{"original.zip":"…","R0B0S0D_cluster_cdl.csv":"…","R0B0S0D_cluster_quality.csv":"…"}}
```

## 浏览器实跑记录

2026-11-19 在 Chrome 从工作台上传实际 ZIP 及上下行两套 CSV，分别下载交换文件、计算结果。逐行比对下载文件与 ChannelEgine 独立命令输出，上下行各 38 帧，末帧编号及链路编号均为 37，时刻 36.17493937675094 秒。对端以原始 CSV 独立复算各方向 190 个复数，最大绝对差分别为 1.718×10⁻²⁰、1.531×10⁻²⁰。该验证覆盖界面、文件转换、计算及下载。

另用生产 Dockerfile 实建 API 镜像，从镜像运行同一导入路由，Chrome 重走上下行上传、交换文件下载、独立计算服务及结果下载。与对端命令输出相比，最大复数绝对差为下行 1.184×10⁻²²、上行 4.524×10⁻²²。替代输入从下行每帧取八条记录，单独配套质量表与清单，声明请求 16 簇。38 帧均保留实际 8 簇和未知适用性，下载结果逐帧五个频偏与独立复算一致。该替代输入用于验证接入行为，未做新的八簇算法精度评估。

## 物理证据

时间由位置、米制假设及恒速推导。时延和角度沿用数据的候选单位，角度为天线局部坐标。跨帧路径身份、帧间真实相位和多普勒谱未知。本次只在原始采样时刻重建单极化模型频响。设备播放、实测精度和正式用途容限均待现场证据。
