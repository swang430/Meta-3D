# 单帧 GCM CLUSTER 离线转换

仅用 Python 标准库，读取一个 JSON，输出一个表头和一行数据。不发送设备命令，不调用 Lauraycs，不生成连续轨迹或正式报告。

```sh
python3 scripts/gcm_single_frame.py scripts/fixtures/gcm_single_frame.json /tmp/gcm-single.csv
python3 -B -m unittest discover -s scripts/tests -p test_gcm_single_frame.py -v
python3 -B scripts/tests/mutate_gcm_single_frame.py
```

模块接口：`convert_frame(frame: dict) -> tuple[dict, list[dict]]`。公共列有序，包含 `TIMESTAMP`；簇按输入顺序返回，导出 `CLUSTER_FIELDS` 为 `CLUSTERID,POWER,DELAY,AoA,AoD,ASA,ASD,ZoA,ZoD,ZSA,ZSD`。输入错误抛 `ValueError`；命令行成功退出 0，错误退出 2，在校验完成前不打开输出文件。输出不能覆盖输入或三份真实来源材料，包含符号链接和硬链接。输出写入期间的文件系统故障仍可能留下不完整文件。

## 输入和来源

样本是**人为构造的合成数据**，用于计算验证，不能作为真实导出或设备验收证据。

- `source.kind` 为 `synthetic` 或 `real`；真实输入必须通过下述独立材料校验，`direction` 为 `downlink` 或 `uplink`。`batch_id` 是同批身份；`raw_paths`、`final_membership`、`cluster_export` 分别记录原始逐径、最终簇成员、簇功率时延的出处，不能为空。公共 `INFO` 列只写来源类别和上下行方向，避免将分隔符混入内容；完整来源保留在输入 JSON。合成输入仅校验声明；真实输入核验文件字节及内容对应关系，但不认证测量真实性。
- `common` 包含样本中的公共列。此版本只接受已对齐 GCM 全局坐标的完整直角坐标，单位米；不自动推测投影、坐标原点或经纬度转换。`TIMESTAMP` 是 `hh:mm:ss.mmm`，本接口强制提供，手册本身列为可选。`SPEEDKMH` 可选，未知应省略，不能填 0 冒充静止。手册说明缺速度时会由位置时间推算，单帧不能据此确定真实速度。
- `rotations.arrival`、`rotations.departure` 是分别作用于原始接收端与发送端方向的局部到 GCM 全局旋转矩阵。按列向量 `v_global = R v_local`；要求正交且行列式为 +1，容差 `1e-9`，反射、缩放不接受。身份矩阵也必须显式填写。
- `paths` 是原始逐径，编号 `id` 唯一，逐条带 `batch_id`、有限 `power_db`、局部方向三分量 `arrival` 与 `departure`。功率必须来自同一口径，按 dB 转换为线性相对功率作为权重。方向可非单位长度，但不能为零。
- `directions.arrival=toward_source` 表示接收端朝向来波源；`propagation` 表示波在接收处的传播方向，需反向。`directions.departure=toward_receiver` 表示发送端朝向出射路径；`opposite_propagation` 需反向。不能凭字段名猜方向。
- `clusters` 是同批最终成员分组，不执行再次聚簇。`id` 为显式帧内局部整数编号，`members` 引用逐径编号，禁止缺失、重复、跨簇重复及静默丢径；目前要求逐径集合与最终成员全集一致，若源算法过滤了路径，需先提供有明确记录的有效逐径集合，不得把不完整输入称为完整原始批次。
- 每簇 `power_db` 为显式导出的绝对簇功率（dB），`delay_ns` 为显式导出的绝对簇时延（ns），原样传递。也接受显式正损耗 `pl_db`，以 `POWER=-pl_db` 转换；或 `delay_s`，以 `DELAY=delay_s*1e9` 转为 ns。两种功率字段或两种时延字段同时出现则拒绝；正损耗须大于零。逐径功率同样可用 `pl_db`，不猜测字段正负含义。不从成员总和替代簇功率，不从最早路径、加权均值或相对时延推导绝对时延。
- `propagation` 为 `LOS` 或 `NLOS`。前者必须存在编号 0，后者不得存在。其余编号互异且非负，最多 24 个非直达簇。不会从最早、最强或角度相近自动认定直达路径。单帧编号不是跨帧跟踪证据，轨迹调用方负责以有来源的映射替换编号并稳定排列。

## 角度定义和手册核对

依据本次提供的 Channel Studio GCM User Guide Revision 15.0（March 2025）：

| 手册位置 | 本实现采用的要求 |
| --- | --- |
| §13，页 81 | CLUSTER 只接受上下行同频，两个中心频率必须相等 |
| §14.1 | 小数点使用 `.`；输出选用分号 `;`，文本由标准 CSV 引号转义 |
| §14.2，表 14-1、14-2，页 87–89 | `CMIMPORTMODE=CLUSTER`、上下行频率、BSID/SID/UEID、两端位置必填；频率严格在 0–100000 MHz 之间；BSID 1–16，UEID 1–64；一个基站最多 8 个不同小区，单帧单链路仅出现一个小区；SID 无手册数值上限，本实现要求正整数 |
| §4.1.1，表 4-2，页 19 | 位置分量范围 ±100000 m，距原点及链路长度严格小于 100000 m；单帧不涉及相邻位置间距；CLUSTER 轨迹按 §13.2.1 的 0.3 m 判定，表 4-2 的通用 1 m 不用于该导入 |
| §13.2.5，页 83–84；§14.2.3，表 14-5，页 89–91 | 原样读取簇参数；功率严格小于 0 dB，绝对时延严格大于 0 ns；直达编号 0；最多 24 个非直达簇；整组簇列的表头和值在同一行逐簇重复，不重复公共列 |
| §14.2.3 | AoA/AoD 在 ±180° 内；ASA/ASD 在 0–104°；ZoA/ZoD 在 0–180°；ZSA/ZSD 在 0–52°。本实现完整提供四个天顶字段，不混用仰角字段；不裁剪超范围结果 |
| §13.2.5；§22.2，页 159 | 全局 +X 向东为方位 0°，朝 +Y 逆时针为正；天顶角朝 +Z 为 0°、地平面 90°、朝下 180°。GCM 下行约定 AoA 由移动端观察，AoD 由基站观察 |

每条方向先归一化、按声明必要时反向，再旋转到全局，以 `atan2(y,x)` 求方位，以 `acos(z)` 求天顶角。原始上行数据的发送端为移动端、接收端为基站，因此输出时交换两端统计，将移动端观察方向写入 AoA/ZoA，把基站观察方向写入 AoD/ZoD；这只是端点角度角色转换，不是上下行功率、频率或信道互易性的证明。

计算定义（本转换器的显式选择，**不是声称手册规定了此算法**）：

1. 成员权重 `w_i = 10 ** ((p_i - max(p)) / 10)`，减最大值只为数值稳定。
2. 方位中心为 `atan2(Σ w sin(a), Σ w cos(a))`；方位扩展为相对中心最短圆周差 `[-180,180)` 的功率加权均方根。
3. 天顶中心为 `Σ w z / Σ w`，天顶扩展为相对该中心差值的功率加权均方根。
4. 方位圆周合向量相对长度不超过 `1e-12` 时中心不唯一，拒绝；方向落在天顶或天底、水平分量不超过 `1e-12` 时方位不可确定，拒绝。绝不置零或猜中心。范围超限拒绝。

## 验证和仍缺的证据

验证命令见开头。端到端测试启动真实 CLI、解析生成文件，并以可手算三维旋转样本独立核对全部 11 个簇字段；另有不等功率、跨 ±180°、方向反转、上行端点角色、直达条件与输入顺序测试。负例覆盖字段缺失、非法数值、错批次、错成员、矩阵缩放/反射/剪切、退化中心、范围超限及拒绝时保留已有输出。变异脚本在临时目录更改实现，再实跑同一批行为测试；不改工作树、不把语法或导入错误算作检出。按用户要求样本和实现先落盘，测试随后运行；红测试证据来自受控变异，不声称完成了实现前红测试。

目前没有具备同批原始逐径、最终成员、真实绝对簇功率时延、两端坐标旋转及方向定义的完整真实样本。仓库已有聚簇 CSV 不能单独补足这些证据，因此本片只提供合成样本验证。不声称已完成 GCM 软件实际导入、真实场景数值验收、硬件回放或跨帧连续性验证。未知来源不得靠 `kind=real` 声明升级为已核验真实数据。

### 用原始单位验证导出
在仓库根目录运行。此例采用 PL = −20 log10(|H|) 的正损耗定义，功率以相同参考值表示。

```sh
jq '.clusters[0] |= (del(.power_db,.delay_ns) + {pl_db:80,delay_s:1e-7})' scripts/fixtures/gcm_single_frame.json > /tmp/gcm-source-units.json
python3 scripts/gcm_single_frame.py /tmp/gcm-source-units.json /tmp/gcm-source-units.csv
cat /tmp/gcm-source-units.csv
```

该帧的 POWER 为 −80 dB，DELAY 为 100 ns。每条记录只能选一种功率表示，每个簇只能选一种时延单位。真实输入须通过下述材料校验，不能仅靠来源标签放行。INFO 只写来源类别和方向。单行使用一套来源方向的模型，包含上下行载频不表示独立重建两个方向。手册 §13.2.2 说明 GCM 会按计算的速度曲线调整时刻。设备播放未验证。

## 真实输入的材料接口

`convert_frame` 和 CLI 接受真实输入。`source` 额外提供非空 `frame_id`，以及 `sha256` 对象，其三个键 `raw_paths`、`final_membership`、`cluster_export` 分别为材料文件的小写 SHA-256。三个来源字段填可读取的绝对文件路径；三份文件不能相同（包含链接别名），内容哈希不能重复，字段比较同时区分类型。程序读取实际字节核对哈希，再解析 JSON，逐项比较；缺材料、改字节、错批次、错帧、错方向或输入与材料不一致均拒绝。

三份材料均包含 `kind=real`、`batch_id`、`frame_id`、`direction`，后三者与输入 `source` 一致。

- 原始逐径材料另包含 `common`、`rotations`、`directions`、`paths`、`propagation`，与输入同名内容完全一致，绑定位置、姿态、方向和逐径。
- 最终成员材料的 `clusters` 是按输入簇顺序排列的 `{id,batch_id,members}` 列表。
- 簇导出材料的 `clusters` 是输入簇去掉 `members` 后的对象列表，保留功率与绝对时延的原字段及单位。

输入示意：`source.sha256.raw_paths` 是 `source.raw_paths` 所指文件的实际字节哈希，其余两份类同。调用方提供原有材料和原有哈希，不得为通过校验而凭空补造材料。测试中的临时材料是人为构造的接口正例，不代表取得了真实测量材料。此机制证明材料之间一致，不证明材料确实由现场测量产生；没有完整真实材料时仍不能宣称真实验收。

内部 `_convert(frame)` 仅执行数值转换，供已完成整套证据核验的轨迹调用方复用；它不验证真实材料，不能单独作为来源认证入口。此脚本没有接入正式报告或正式测试判定。
